# 晚间节点 + 承诺优先填充 + 邮件→滴答自动写入

> 设计日期：2026-08-03
> 状态：待实现

## 问题来源

1. **晚间时间无安排**：工作日 17:30 日终收尾后到 23:00 复盘之间有 5.5 小时空白，用户下班回家后的时间没有节奏引导。
2. **邮件承诺丢失**：用户通过邮件表达了意图/承诺后，系统知道用户要做什么，但没有自动写入滴答清单，导致承诺被遗忘。
3. **节点偏「问」不偏「填」**：现有 Cron 节点的开启动作以泛泛询问为主（「想做什么？」），而非从已有数据自动填充候选计划。

## 设计概述

三个核心改动：

1. **新增晚间三节点**（20:00 / 21:00 / 22:00，仅工作日），复盘从 22:30 迁移至 23:00
2. **全节点统一「承诺优先填充」**：每个节点的开启动作从泛泛询问改为从多数据源拉取候选动作、自动填充、呈现确认
3. **邮件意图 → 滴答自动写入**：Phase 4 新增 `task_commitment` 分类，Phase 5 自动创建滴答任务

## 一、晚间时间节点

### 1.1 节点定义

晚间新增 3 个节点，仅工作日运行。休息日保持现有 4 节点骨架，晚间不加块。

| # | 时间点 | 触发方式 | 运行条件 | 回顾 | 开启 |
|---|--------|---------|---------|------|------|
| E1 | **20:00** | Fixed Cron | 仅工作日 | 回顾今日白天执行摘要（17:30 收尾结论）+ 近 7 天晚间四类覆盖快照 | 开启晚间第一块：已有承诺优先填充 + 覆盖缺口建议，询问用户调整 |
| E2 | **21:00** | Fixed Cron | 仅工作日 | 回顾第一块实际做了什么，是否按计划推进 | 开启第二块：按第一块已覆盖类别调整建议，切换还是继续 |
| E3 | **22:00** | Fixed Cron | 仅工作日 | 回顾第一、二块执行 | 开启第三块：晚间最后一小时，该收束的收束 |
| N | **23:00** | Fixed Cron | 每日 | 回顾晚间三块（仅工作日）+ 全天执行全貌 | 次日预览；休息日轻量复盘（原 22:30 复盘内容完整迁移） |

### 1.2 晚间节点的特殊规则

- **语气更轻**：晚间是个人时间，用「想做什么」而非「该做什么」，不追进度
- **无 +5/+10 min 动态 Timer**：晚间节点不催促，用户不回就跳过，E2 节点正常触发
- **休息日不执行**：休息日晚间自由节奏，不加块
- **类别自动判定**：用户在一个块里的活动，系统根据关键词自动归类（精进/休闲/锻炼/副业），写入 daily，不需要用户手动分类

### 1.3 晚间三块的填充方式（E1）

```
第一层：已有承诺优先

从以下数据源拉取可晚间执行的候选：
  - commitments.md：goal/step 标记了四类标签且状态为 pending
  - 长期目标拆解：TELOS 各领域的下一步可晚间执行动作
  - 习惯追踪：设定的习惯（如「每周跑2次」），本周次数未达标
  - 邮件提取的承诺：Phase 4 识别但尚未安排时间的意图

第二层：覆盖缺口兜底

当第一层候选不足时，读取近 7 天晚间四类覆盖快照，
找出覆盖最少或连续缺失的类别做建议。

填充呈现：
  「晚上好。今晚有三块时间：
    1. ___（已有承诺填充）
    2. ___（覆盖缺口建议或第二个承诺）
    3. ___（留白，用户自由填充）
    上面是我根据你之前的计划拼的，想怎么调整？」
```

### 1.4 四类定义与判定

| 类别 | 关键词 | 示例活动 |
|------|--------|---------|
| 精进 | 看书、读、纪录片、课程、学、练习 | 读《深度工作》、看纪录片、上线上课 |
| 休闲 | 刷剧、游戏、随便、休息、放松、躺 | 看剧、打游戏、刷手机、发呆 |
| 锻炼 | 跑步、健身、运动、走、跳、游泳 | 跑步 5km、健身房、散步 |
| 副业 | 副业、项目、赛道、搞钱、研究 | 研究 AI 赛道、搭副业网站 |

## 二、全节点统一「承诺优先填充」

### 2.1 核心原则

每个时间节点的「开启」动作从泛泛询问改为结构化的自动填充：

```
1. 从多数据源拉取候选动作
2. 按优先级排列，自动填充到对应块
3. 呈现给用户确认（「我帮你排了一下，看看要不要调」）
4. 用户调整 → 更新方案；用户不回 → 按填充方案默认执行
5. 填充结果同步写入滴答清单
```

### 2.2 各节点填充来源

| 节点 | 填充来源 | 输出 |
|------|---------|------|
| 09:30 | commitments 今日到期 + 昨日复盘未完成 + 长期目标下一步 + 滴答今日任务 | 全天计划草案 |
| 10:30 | 09:30 计划中当前段的未推进项 | 轻量提醒，不重排 |
| 14:30 | commitments 本周末到期前置条件 + 上午未完成项自动延续 | 下午 1-2 件重点 |
| 15:30 | 14:30 确定事项是否卡住 | 建议切换/继续 |
| 16:30 | commitments 今日到期但全天未提及的漏网之鱼 | 收尾前抓漏 |
| 17:30 | —（收尾为主，不填充） | — |
| 20:00 | commitments 四类标签 + 长期目标晚间可执行步骤 + 习惯缺口 + 邮件提取意图 | 晚间三块填充 |
| 21:00 | 第一块执行结果 | 调整/继续 |
| 22:00 | 前两块执行结果 | 最后一小时收束 |
| 23:00 | —（复盘为主，不填充） | — |

### 2.3 用户调整方式

收到填充方案后用户可以：
- 「1 换成 ___，其他不变」→ 覆盖单个块
- 「今天只想 ___」→ 全部覆盖
- 「今晚不想做这些，只想休息」→ 全部降级为休闲，不做道德评判
- 不回复 → 按填充方案默认执行，下次节点回顾时确认

## 三、邮件意图 → 滴答自动写入

### 3.1 整体链路

```
用户回复邮件（含意图/承诺）
  → Phase 4 理解：识别为 task_commitment
  → Phase 5 行动：
      1. 调用滴答 MCP create_task 创建任务
      2. 写入 commitments.md 作为追踪备份
      3. 回复用户确认：「已帮你加到滴答清单，预计什么时候做？」
  → 下一 Cron 节点：从滴答拉取今日任务，自动填入计划
```

### 3.2 Phase 4 新增分类

| 分类 | 匹配模式 | 处理方式 |
|------|---------|---------|
| `task_commitment` | 「我要/得/准备/打算/应该做 X」「下次 X」「明天 X」「周末 X」「有空的时候 X」等 | Phase 5 自动创建滴答任务 + 确认邮件 |

与现有 `plan_adjustment`（调整已有计划）区分——`task_commitment` 是新任务创建。

### 3.3 任务创建的智能推断

| 用户说的 | 推断 |
|---------|------|
| 「今天要看完报告」 | `due_date: 今天`, `priority: 中` |
| 「周末整理书房」 | `due_date: 本周六`, `priority: 低` |
| 「明天记得交报销」 | `due_date: 明天`, `priority: 高`（硬截止） |
| 「有空的时候看看那个课程」 | `due_date: 空`, `priority: 低`, `tags: 精进` |
| 「下次要去跑步」 | `due_date: 空`, `priority: 低`, `tags: 锻炼` |
| 「得研究一下这个副业方向」 | `due_date: 空`, `tags: 副业` |

推断规则：时间词 → `due_date`，动作紧急性暗示 → `priority`，内容语义 → `tags`/`project_id`。

### 3.4 Cron 填充计划同步写入滴答

各 Cron 节点自动填充好计划后，同步调用滴答 MCP 创建对应任务：

| 节点 | 写入滴答内容 |
|------|-----------|
| 09:30 | 填充的今日计划项 → 滴答任务（`due_date: 今天`） |
| 14:30 | 延续的下午重点事项 → 滴答任务（`due_date: 今天`） |
| 20:00 | 晚间三块填充 → 滴答任务（`due_date: 今天`, `tags: 晚间/精进/锻炼等`） |
| 邮件回复时 | 用户意图即时创建为滴答任务 |

**幂等处理**：创建前先查今日任务列表，标题匹配则跳过，避免重复。

### 3.5 滴答未配置时的降级

沿袭现有降级路径——写入 `commitments.md` 并标记 `[待同步到滴答]`。滴答 MCP 恢复后批量同步。

## 四、数据增强

### 4.1 commitments.md step 增加类别列

```markdown
| # | step | 类别 | 目标日期 | 状态 |
|---|------|------|---------|------|
| 1 | 读《深度工作》第1-3章 | 精进 | 2026-08-05 | pending |
| 2 | 研究 AI 副业赛道 | 副业 | 2026-08-06 | pending |
| 3 | 跑步 5km | 锻炼 | 每2天 | pending |
```

类别列可选——不填时晚间系统不强行归类，只凭关键词实时判定。

### 4.2 晚间四类覆盖快照

当日晚间复盘时，系统自动判定每个晚间块归属的类别并写入 daily：

```markdown
## 晚间
- 20:00-21:00: 看《深度工作》（精进）
- 21:00-22:00: 跑步 5km（锻炼）
- 22:00-23:00: 刷剧放松（休闲）
```

E1 节点读近 7 天 daily 中的「晚间」段，统计四类出现次数，生成覆盖快照。

## 六、不做什么

- 不做晚间专属统计仪表盘（后续迭代考虑）
- 不做复杂的 NLP 意图识别（先用规则匹配）
- 不给休息日加晚间节点
- 用户说「晚间的计划不对」系统调整但永不追问、不做评判
