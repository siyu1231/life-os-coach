# 邮件触发信号

本文件定义 review skill 的三类邮件触发信号及对应的邮件模板。

## 1. 晚间复盘信号（evening-review）

**触发时机**：每日 23:00 定时发送（三种模式的消息模板不同，见 `engine/cron-system.md` 的晚间节点行为章节）。

**目的**：帮助用户在一天结束时做结构化反思，从经历中提取学习，而不是沉迷于自责或流水账。

**邮件模板 A：工作日晚间复盘**

```
主题：今天过得怎么样？一起回顾五分钟

{昵称}，今天辛苦了。

睡前花五分钟，问自己几个问题。不用写很多，想到什么就告诉我什么：

1. 今天你最满意的一个时刻是什么？
2. 今天有什么事情让你感到"靠近了目标"？
3. 今天有没有什么地方和预期不一样？
4. 今天最消耗你精力的是什么？
5. 如果明天只改一件事，你会改什么？

回复任意一个数字或你的想法，我们今晚就聊到这里。明天再继续。
```

**邮件模板 B：周末/节假日晚间复盘**

```
主题：这周（这几天）过得怎么样？来一次轻柔复盘

{昵称}，晚上好。

假期/周末的节奏和工作日不一样，复盘的方式也不一样。不追求效率，只关心这段时间带给你什么：

1. 这几天最让你感到放松或舒服的时刻是什么？
2. 有没有什么小惊喜、有趣的事或意料之外的收获？
3. 什么事情让你觉得"时间花得值得"？
4. 有什么事情或情绪在反复出现？
5. 休息过后，你最想重新启动的一件事是什么？

不用着急，想到哪条说哪条。复盘也可以是轻松的。
```

**模板说明**：

- 5 个问题覆盖：正向体验、目标靠近度、偏离感知、消耗识别、最小调整。
- 工作日版本侧重行动和目标，周末版本侧重恢复和感受。
- 用户回复任意一个问题即可，不强求全部回答。
- 根据用户回复的深度决定后续对话：简短回复则不再追问；深度回复则引导至完整复盘流程。

## 2. 用户主动复盘信号（user-initiated-review）

**触发时机**：用户主动发来类似"这周又废了""感觉什么都没做成""我想复盘一下"等语句。

**目的**：快速响应用户的复盘需求，帮助用户从情绪化自我评价转向结构化复盘。

**邮件模板 A：用户表达"这周又废了"**

```
主题：先不看"废了"的地方——这周有没有做过对的事？

{昵称}，听到你这么说，我猜你心里有很多"没完成"的事在排队。

但在我听你讲没做到的部分之前，我们先做一件事：这周你有没有哪怕一件——做完了、推动了、或者让你觉得还不错的事？

不用大。只要一件。

告诉我，我们从这个开始。
```

**邮件模板 B：用户想复盘（通用）**

```
主题：好的，我们来复盘

{昵称}，好。我们先定一下范围：

这次你想复盘的是：
1. 一天？一周？一个项目？还是某种反复出现的模式？
2. 你最想通过这次复盘回答什么问题？
3. 聊完之后你想带走什么？一个洞察、一个调整，还是一种理解？

先回答第一个问题就够了，后面的我们慢慢来。
```

**模板说明**：

- 用户说"废了"时，先帮助用户打破全盘否定的惯性，强制找到一件做对的事。
- 用户表达复盘意愿但不清楚范围时，用三个问题帮用户聚焦。
- 不追问"为什么废了"，而是引导重建事实和有效做法。

## 3. 日间收尾信号（daily-wrap-up）

**触发时机**：每个工作日 17:30 发送。

**目的**：在一天工作结束前做一次轻量回顾，为晚间深度复盘做准备，也帮助用户区分"今天到此为止"和"还要继续"。

**邮件模板**：

```
主题：今天收工前，三个快速问题

{昵称}，下午好。在结束今天主要工作之前，花一分钟想三个问题：

1. 今天哪件事做得还不错？
2. 哪件事还没做完，需要明天继续？
3. 现在状态怎么样——需要休息了，还是可以再做一点？

不用回很长。三个字、一句话都可以。
知道你在哪，我就知道怎么帮你安排今晚和明天。
```

**模板说明**：

- 17:30 是很多人的工作收尾时间，问题设计为"轻量级"——三选一回答即可。
- 问题覆盖：成就正向强化、未完成项记录（为晚间复盘准备）、精力状态判断。
- 用户回答后，根据状态决定后续：如需休息则不再打扰；如有能量则可引导做一点晚间活动规划。
- 不要求用户完整回答三个问题，回复一个即可。
