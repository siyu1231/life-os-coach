# 拖延应对邮件触发器

## 触发信号

以下邮件信号表明用户可能需要拖延应对与执行技能的介入：

### 连续未推进信号

- 同一任务连续 2 个时段（如上午和下午、今天和明天）均无进展
- "这个事还是没动……"
- "昨天也说要做的，结果又拖过去了"
- "一天过去了，最重要的事一点没做"

### "不想做"信号

- "我就是不想做"
- "真的不想动"
- "一想到要做就烦"
- "没有做的意愿"

### "没动力"信号

- "没有动力"
- "提不起劲"
- "状态不好，不想干活"
- "知道自己该做，但就是没有推动力"

### "等一下"信号

- "等一下再做"
- "等会儿再说"
- "先休息一下"
- "先刷会儿手机"
- "等我准备好了再开始"

## 回应模板

### 模板 A：连续未推进——压缩任务大小

```text
我注意到这个任务你已经放在那里一段时间了。这不代表你做不了，而是可能这件事的启动门槛比你以为的高。

我们试试把它再拆小一点：这个任务有没有一个 2 分钟版本？比如只做第一行、只打开文件、只写一句话。先做那个最小的，做完告诉我感受如何。
```

### 模板 B："不想做"——2 分钟启动法

```text
"不想做"本身是个信号——它不一定是坏事，而是在告诉你这件事的阻力有点大。

不用强迫自己做很久。试着告诉自己：只做 2 分钟。2 分钟后如果还是不想做，就停下来。通常开始之后，继续下去会更容易。你愿意试试吗？
```

### 模板 C："没动力"——识别阻力类型

```text
"没动力"是一个笼统的感受，背后可能有不同的原因。是这件事太难？太模糊？太烦？还是你太累了？

如果用一个词形容你现在不想做的原因，会是什么？先把这个原因找出来，我们就能找到更有针对性的方法，而不是硬撑。
```

### 模板 D："等一下"——换环境建议

```text
如果在这个环境里总是"等一下"，可能是因为环境中的某些东西在触发拖延——手机、沙发、床、电视。

试着换一个环境：去另一个房间、去楼下、去一个咖啡馆或图书馆。有时候不是你不想做，而是你所在的位置让你很难开始。
```

### 模板 E：综合回应——降低门槛 + 换环境

```text
拖延通常不是意志力问题，而是环境 + 任务门槛的共同作用。我们可以同时做两件小事：

1. 把任务压缩到 2 分钟内能开始的程度——只做最微小的一步。
2. 换到一个有助于行动的环境——哪怕只是换一张桌子。

现在你愿意先做哪个：先拆任务，还是先换地方？
```

## 何时引导用户到 Chat/CLI

以下情况必须在邮件中引导用户切换到 Chat 或 CLI 进行深度对话：

1. **拖延模式深**：用户表达长期慢性拖延（"我从小拖到大"、"很多领域都动不起来"），需要系统性的练习框架而非一次性建议。
2. **伴随严重情绪困扰**：用户表达强烈的自我批评、羞耻、焦虑或抑郁情绪。
3. **复杂场景**：涉及多个任务相互卡住、完美主义与决策拖延叠加、或耗竭与拖延交织。
4. **需要持续追踪**：用户需要多次复盘、调整启动条件、或持续记录拖延回路。
5. **用户明确需要深入对话**：用户说"这个问题很大""我想聊聊我怎么总拖延"。

### 不需要引导的情况

- 用户只是抱怨一句"今天不想动"，给予简短鼓励即可。
- 用户回应了压缩任务或换环境的建议并已开始行动。
- 用户已经在 Chat/CLI 对话中，邮件只是补充记录。

## 引导用语

```text
这个话题值得认真聊。拖延有时不是一个方法就能解决的，需要我们在对话中慢慢找到你的模式。建议你切换到 Chat 或 CLI 模式，我们从头开始，从你最当下的感受和场景入手。可以直接回复"切换模式"。
```

```text
你提到的拖延模式我听到了，而且我猜这不是第一次了。如果这个模式已经持续一段时间，建议我们切换到 Chat 做一次完整的阻力识别和启动设计。你现在已经迈出了重要一步——注意到了它。
```
