# 邮件触发信号

本文件定义 planning skill 的三类邮件触发信号及对应的邮件模板。

## 1. 每日启动信号（daily-startup）

**触发时机**：每个工作日 09:30 定时发送。

**目的**：帮助用户以最小认知负荷开始新的一天——明确今天最重要的事，而不是被待办淹没问题。

**邮件模板**：

```
主题：早安——今天想先做什么？

{昵称}，早上好。

新的一天开始了。在事情涌进来之前，先花一分钟想一个问题：

如果今天只完成一件事，哪件事会让这一天「没有白过」？

不用列很多。
不用排优先级。
不用拆步骤。

就一件事。

等你准备好了，告诉我就好。我们一起把今天安排成「能执行」的样子。
```

**模板说明**：

- 不要求用户列完整待办，只引导「最小聚焦」——一件事。
- 使用「如果……那么……」句式降低启动阻力。
- 不预设用户有精力回复，提供简单回应入口即可。
- 如果前一天有未完成项，在邮件末尾追加一句：「对了，昨天 XX 还没完成。你想今天继续，还是先放一放？」

## 2. 改计划信号（plan-modification）

**触发时机**：用户主动回应要求调整计划（如「今天临时有会」「状态不好」「计划变了」）。

**目的**：快速响应用户的计划变动需求，帮助用户在新约束下重新找到可执行的重点。

**邮件模板 A：用户主动提出调整**

用户发来类似「今天计划打乱了」「下午有临时会议」「XX 做不了」时使用：

```
主题：收到，我们来调一下

好的，计划本来就是为变化准备的。

我们先确认几件事：

1. 今天原本计划里，还有哪件是你仍然想做的？
2. 哪件可以先推到明天？
3. 新增的事项里，哪一件最重要？

不用全想好，先告诉我第一点就可以了。剩下的我来帮你整理。
```

**邮件模板 B：Agent 发现偏离后主动询问**

当 Agent 在 CHECK 阶段发现显著偏离但用户未主动说明时使用：

```
主题：今天的计划好像有点偏离，需要调整吗？

{昵称}，我注意到今天（原计划的 XX）目前还没有进展。
这不一定是问题——可能计划本身就不准。

如果你想调整，告诉我：
- 现在什么更值得做？
- 还是想保持原计划，只是晚一点开始？

无论哪种，都没问题。按你现在的节奏来。
```

**模板说明**：

- 不追问「为什么会偏离」——偏离是数据，不是审问。
- 给用户明确的选择权：「继续原计划」或「调整」。
- 每次只问一个最关键的问题，不让用户感到压力。
- 调整后的计划写回本地计划和滴答清单，并做 VERIFY。

## 3. 收尾未完成项处置信号（end-of-day-unfinished）

**触发时机**：每个工作日 17:30，检测到当日计划中有未完成的任务项。

**目的**：帮助用户在一天结束时对未完成项做出决定——推至明天、降级为可选、或主动放弃——避免累积心理负担。

**邮件模板 A：有少量未完成项**

当未完成项 <= 3 件时使用：

```
主题：今天还没来得及完成的几件事

{昵称}，辛苦了。

今天的计划里有几件还没完成：
1. {事项 A}
2. {事项 B}

不用今晚赶完。你可以决定：
- 🔄 推到明天——我帮你放进明天的计划里。
- 📦 降级为「有空再做」——不设截止日。
- ❌ 放弃——确认不需要做了。

回复数字或文字告诉我就好。无论怎么选，今天做成的部分已经在向前推进了。
```

**邮件模板 B：有较多未完成项**

当未完成项 > 3 件时，先引导用户聚焦最重要的一件：

```
主题：今天没完成的事有点多——我们先只处理一件

{昵称}，今天计划里还剩下 {N} 件没完成。
这本身就在告诉你：今天的计划容量可能预估得偏满了。

不用一次处理所有。今晚只选一件最重要或最紧急的未完成项，告诉我：
- 推到明天？
- 还是降级/放弃？

其余的我来帮你推迟到本周其他日期，或在周计划里重新安排。

明天做计划时，我们会根据今天的数据把容量调得更准一些。
```

**模板 C：连续多日未完成**

当同一任务连续 3 天以上出现在未完成列表中时使用：

```
主题：关于 XX，我们可能需要重新看看

{昵称}，我注意到 XXX 已经连续 X 天出现在「未完成」里了。

这可能不是时间不够的问题，而是这件事本身需要重新评估。我们不一定非要「做完它」。你可以考虑：
- 这个任务现在还重要吗？——它的优先级有没有变？
- 它太大需要拆？——拆到多小你能启动？
- 它其实不该做？——承认了也没关系。

告诉我就好。有些事放下比硬扛更明智。
```

**模板说明**：

- 日终信号只关注「决策」，不追求「完成」。
- 给三种明确的处置选项（推迟/降级/放弃），降低决策负荷。
- 当模式重复出现时（连续多日），发出更深层的信号——任务本身可能有问题。
- 每次收尾信号后，将用户的决定同步到滴答清单（推迟=改截止日，降级=改优先级，放弃=标记完成或删除）。
- 用户未回复时，默认将未完成项推迟到次日（不追问、不催促）。
