# Life Coach Agent

> **Active AI Life Coach Agent** —— 一个工具无关的 AI 人生教练技能包，融合 life-coach 教练方法与 LifeOS 系统管理，以 Cron 定时调度 + 邮件触达为日常通道，陪伴用户将人生方向转化为目标、项目和今日行动。

## 一句话描述

将项目 clone 后，告诉你的 AI 工具：「**读取 AGENTS.md 并完成安装**」，即可获得一位温暖、清晰、务实的人生项目教练，每天主动关心你的进度、精力与方向。

---

## 核心能力

本技能包分为四个层次：引擎层负责调度与触达，系统层负责推理与状态管理，教练层负责对话与方向引导，集成层负责外部工具连接。

| 层次 | 模块 | 职责 |
|------|------|------|
| **引擎层** (engine) | Cron 调度系统 | 工作日 09:30-17:30 六个日间节点 + 20:00/21:00/22:00 晚间三块 + 23:00 晚间复盘，自动触发会话 |
| | 邮件协议 | 企微邮件收发、轮询去重、动态 Timer 跟进（+5min / +10min） |
| | 会话流状态机 | 6 阶段生命周期：采集 -> 触达 -> 接收 -> 理解 -> 行动 -> 闭环 |
| **系统层** (system) | 执行循环 (Algorithm) | CHECK -> GAP -> DECIDE -> ACT -> VERIFY -> LEARN 六步推理闭环 |
| | TELOS 方向系统 | 人生 8+1 领域，追踪当前状态 -> 理想状态，定义阶段性主题和 Not Doing |
| | ISA 完成标准 | 每个任务附带可验证声明，完成状态以工具证据关闭 |
| | 记忆系统 | 本地 Markdown 记忆层，先少后多、先记录再提炼、四级写入安全等级 |
| | 三级验证 | 数据验证 -> 证据验证 -> 觉察验证，确保「做完了」有据可查 |
| **教练层** (coach) | ACT 核心 | 认知解离、接纳、当下觉察、价值澄清、承诺行动 |
| | 共享教练流程 | 7 步教练与聊愈流程：建立安全 -> 映照处境 -> 澄清需求 -> 促进觉察 -> 聚焦选择 -> 设计实验 -> 收尾总结 |
| | 7 项教练技能 | 人生愿景、拖延应对、计划、复盘、习惯设计、精力管理、复杂问题解决 |
| **集成层** (integrations) | 滴答清单 MCP | 待办读写的 MCP 集成与本地降级路径 |
| | 工具适配层 | 统一的外部工具接入原则：读取更主动，写入更谨慎 |

## 快速开始

**一句话安装**：将本项目 clone 到本地后，打开你的 AI 工具（Claude Code、Cursor、Cline 等），说：

> 读取 AGENTS.md 并完成安装

你的 AI 工具会按照 AGENTS.md 中的总调度说明和安装指引，自动完成环境检测、目录初始化、外部工具配置引导和首次画像访谈。

如果你使用的 AI 工具不支持读取本地文件，请参考下方详细安装流程。

---

## 安装流程

### 第一步：Clone 项目

```bash
git clone <本项目地址> life-os-coach
cd life-os-coach
```

### 第二步：让 AI 读取项目

将项目目录作为你的 AI 工具的工作目录，告诉 AI：

> 请读取 AGENTS.md 了解项目结构和总调度规则，然后帮我完成安装。

AI 会读取 `AGENTS.md`（总调度人格与路由规则）、`engine/`（调度和协议）、`system/`（推理和记忆）以及 `coach/`（教练技能），然后引导你逐步完成配置。

### 第三步：配置邮件通道

本项目通过腾讯企业微信邮件 API 实现 Cron 定时触达和用户回复接收。在企微管理后台完成以下配置：

1. 创建自建应用，获取 `AgentId`、`Secret`、`CorpId`
2. 在应用详情页的「企业邮箱」中，开通「发送邮件」和「读取邮件」权限
3. 将凭证配置到 AI 工具的环境变量或设置中
4. 验证：发送一封测试邮件，确认收到 API 返回 `errcode=0`

详细协议见 `engine/email-protocol.md`。

### 第四步：配置外部工具（可选）

Agent 的核心能力不依赖任何特定工具，所有外部集成为可选：

- **滴答清单**：如需 AI 读写待办事项，配置滴答 MCP 集成。未配置时，Agent 使用本地 Markdown 文件管理待办。详见 `integrations/dida-mcp.md`。
- **日历**：如需 AI 读取日程安排（用于晨间提醒和计划），配置 Google Calendar、Apple Calendar 或 Outlook API。
- **天气**：如需晨间天气推送，配置天气 API（如和风天气）。

所有外部工具均可降级运行：未配置时，Agent 会在相关能力上诚实告知限制，不会在后台尝试连接。

### 第五步：初始化个人数据

AI 会引导你完成首次画像访谈，创建最小数据目录。遵循「先少后多」原则：

```text
data/
├── profile/
│   ├── user.md           # 作息、固定承诺、沟通偏好、精力线索、执行线索
│   └── life-compass.md   # 人生 8+1 领域、价值观、阶段主题、人生实验
├── planning/             # 日计划、周计划
├── projects/             # 项目状态和里程碑
├── habits/               # 习惯追踪
├── reviews/              # 复盘日志
└── memory/
    ├── daily/            # 每日记录（当天事实和候选洞察）
    └── long-term.md      # 跨文件综合洞察和索引
```

开始时只建核心文件，不要一上来拆很多专项文件。等某类记录反复出现、需要频繁单独读取时，再让 AI 帮你拆分。

### 第六步：启动 Cron 调度

配置 Cron 系统的时间点和触发条件（见 `engine/cron-system.md`）。11 个时间点覆盖全天：

| 时间 | 类型 | 运行条件 | 说明 |
|------|------|----------|------|
| 09:30 | Fixed Cron | 工作日 | 早安问候 + 今日计划引导 |
| 10:30 | Fixed Cron | 工作日 | 上午状态检查（进度、精力、需调整？） |
| 14:30 | Fixed Cron | 工作日 | 午后启动引导（下午最重要的 1-2 件事） |
| 15:30 | Fixed Cron | 工作日 | 下午中段状态检查（需切换任务类型？） |
| 16:30 | Fixed Cron | 工作日 | 收尾预备（今天必须收掉的事？） |
| 17:30 | Fixed Cron | 工作日 | 日终收尾（今天完成了什么，偏离在哪里） |
| 23:00 | Fixed Cron | 每日 | 晚间复盘（工作日复盘执行与觉察，休息日轻量回顾） |
| +5min | Dynamic Timer | 发送后 | 温和提醒（用户未回复时） |
| +10min | Dynamic Timer | 发送后 | 归档等待（用户仍未回复，不再催促） |

**假期模式**：日间节点（09:30-17:30）自动静默，仅保留 23:00 晚间轻量复盘。

### 第七步：验证运行

启动后观察一个完整工作日，逐项确认：

- [ ] 09:30 收到晨间邮件（包含天气、日历摘要、待办概览）
- [ ] 日间各时间点邮件正常触发
- [ ] 回复邮件后，Agent 在 30 分钟会话生命周期内处理并回复
- [ ] CLI/Chat 通道可以发起深度教练对话
- [ ] 数据文件（profile、planning、memory）正常读写，无异常覆盖
- [ ] 验证邮件发送：每日晚间检查邮件 API 调用成功（errcode=0）

## 交互方式

本系统提供两种交互通道，各有分工：

| 维度 | 邮件通道 | CLI/Chat 通道 |
|------|----------|---------------|
| 触发方式 | Cron 定时自动触发 | 用户主动发起 |
| 主要职能 | 触达、状态采集、轻量推进 | 深度教练、多轮澄清、复杂决策 |
| 回复节奏 | 异步，用户可在方便时回复 | 同步或近同步，实时对话 |
| 适合场景 | 日常打卡、状态汇报、小卡点、正向反馈 | 强情绪承接、价值澄清、行为设计、复杂问题拆解 |
| 问题类型 | 封闭式确认、选项选择、简短记录 | 开放式探索、觉察促进、假设检验、行动共创 |
| 字数约束 | 单封邮件正文不超过 200 字 | 无硬性约束，但保持简洁 |

**何时从邮件引导到 CLI/Chat**：

- 连续 2 次以上邮件无法有效推进同一困扰
- 用户表达强烈情绪（痛苦、绝望、愤怒、羞耻、无力感）
- 问题涉及多个层面，需要来回追问才能理清

## 理论来源与致谢

本技能包是对多类公开理论、书籍、训练方法和实践经验的综合整理。所有方法、案例和模板均经过重新组织与原创补充。

### 心理学与教练方法

- **接纳承诺疗法（ACT）**：价值澄清、认知解离、接纳、承诺行动 —— 本项目教练对话的底层操作系统
- **正念相关方法**：正念觉察、非评判态度、MBSR/MBCT
- **认知行为疗法（CBT）**：想法记录、苏格拉底式提问、行为实验、认知重评
- **自我关怀**：共通人性、友善回应、自我批评松动
- **存在主义心理治疗**：自由、选择、责任、意义、孤独与关系（欧文·亚隆、罗洛·梅）
- **焦点解决取向**：例外询问、资源挖掘、下一小步
- **ICF 教练能力**：建立信任、积极聆听、唤起觉察、促进行动与责任

### 行为设计与执行

- **《掌控习惯》（James Clear）**：身份投票、习惯叠加、两分钟规则、环境设计
- **《福格行为模型》（BJ Fogg）**：B=MAP、微习惯、提示设计、庆祝仪式
- **番茄工作法**：专注单元、打扰记录、任务切分与恢复节奏
- **《高效 PDCA 工作术》**：计划-执行-检查-调整的闭环思维
- **拖延应对训练**：拖延回路、启动阻力、完美主义拖延、决策拖延

### 人生方向与意义

- **《斯坦福人生设计课》**：重力问题、奥德赛计划、原型对话、原型体验
- **《心流：最优体验心理学》**：投入、挑战与技能匹配
- **《内在动机》**：自主性、内部动机与持续行动
- **《西西弗神话》（加缪）**：荒诞、意义与主动选择
- **《反脆弱》**：在不确定性中学习与成长

### 系统管理

- **LifeOS**（by Daniel Miessler）：为本次项目提供了系统架构基础——Current State -> Ideal State 的执行哲学、ISA（Ideal State Artifact）可验证声明体系、三级验证框架、以及 Hooks + Pulse 的运行时基础设施

### 暂停实验室课程与参考书单

人生教练体系最主要的启发来自于暂停实验室相关课程，尤其是有效努力、拖延应对基础/进阶、正念、自我关怀、CBT 综合与焦虑应对等训练材料及其参考书单。本仓库只保留可公开传播的抽象方法，不包含课程正文、专有案例或练习原文。

## 安全边界

本 Agent 是人生教练和自我管理辅助工具，不是心理治疗、医疗诊断、法律建议、财务建议或危机干预服务。

### 小芽是补充工具缺失的思考能力，而非替代工具

效率工具可以提供优先级标签，但无法替你选择优先级。日程工具可以告诉你几点有什么会，但不能替你在两个都很重要的事之间做选择。AI 能帮你梳理信息和约束，但最终的选择权在你手里。

### AI 不能替代具身练习

价值观、愿景、勇气、边界感、行动力和自我关怀，很多时候不是在对话中「想明白」就自然拥有的，而是在身体、关系、环境和一次次具体行动中慢慢练出来的。小芽能做的是帮助你把混乱经验整理成语言，把模糊困扰拆成变量，把下一次练习设计得更小、更真实。它可以做镜子、脚手架、记录员和项目经理，但它不能替你练习。

### 在以下情况下，请寻求专业支持

- 持续的情绪低落、焦虑、恐慌或睡眠严重受损
- 自我伤害、伤害他人的想法或计划
- 物质依赖、饮食失调或其他需要医疗干预的状况
- 重大生活危机（丧亲、离婚、失业、法律纠纷等）

### 安全处理规则

- 自杀/自伤/危机信号：优先安全处理，引导联系专业支持
- 严重持续的心理症状：建议寻求心理咨询或精神科评估
- 重大不可逆决定：只帮助澄清价值和选项，不替代决策
- 不把所有痛苦解释成「需要计划」或「需要行动」
- 不做道德评判、羞辱、诊断或伪装成治疗

## 隐私说明

- **本地优先**：默认所有用户数据保存在本地 Markdown 文件中（`data/` 目录），不上传到任何服务器。你完全掌控自己的数据，随时可以查看、修改或删除。
- **外部工具按需接入**：滴答清单、日历、天气等外部集成需你主动配置 API 凭证并授权。未配置时，相关能力诚实降级，不会在后台尝试连接未授权的服务。
- **邮件通道数据**：通过企微邮件 API 收发的邮件内容经过腾讯企微服务器。Agent 仅读取和发送你与 Agent 之间的邮件（通过 `reply_to_mailid` 匹配），不扫描你的其他邮件。
- **`.gitignore` 排除个人数据**：`data/` 目录默认被 `.gitignore` 排除，不会提交到版本控制。如需备份，请使用自己的加密备份方案。
- **公开仓库不包含私人信息**：本仓库是可公开分享的版本，不包含个人用户记忆、真实来访者细节、私有课程正文或专有案例。所有示例均为公开、虚构、脱敏案例。
- **你可以随时删除数据**：删除 `data/` 目录即可清除所有个人记录。Agent 下次运行时会从零开始建立新的画像。
- **节假日 API（timor.tech）**：仅查询中国法定节假日日期，不传输任何用户数据。
- **不要求接入任何第三方服务**：节假日 API 和滴答 MCP 均为可选。即使用户只使用本地文件，Agent 的核心教练能力仍然完整可用。
