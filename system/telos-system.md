# TELOS：人生方向系统——从当前状态走向理想状态

本文件定义 Life Coach Agent 的 TELOS 系统——一个将 LifeOS TELOS 理念与人生罗盘模板相结合的**方向管理系统**。TELOS 回答的核心问题是：**「你现在在哪里？你想去哪里？这一小段路先做什么？什么暂时不做？」**

TELOS 不是一次性的使命宣言，而是一个**随生活阶段不断校准**的动态系统。

## 一、什么是 TELOS

### 1.1 定义

**TELOS**（源自希腊语 τέλος，意为「目的」「终点」「终极方向」）在 Life Coach Agent 语境中，是一个融合了 LifeOS TELOS 理念和 life-coach 价值观罗盘的方向管理系统：

- **来自 LifeOS TELOS**：核心世界观「每个任务都是一次从 Current State 向 Ideal State 的爬山运动」（见 `system/algorithm.md` 第 1.1 节）。TELOS 将这一理念从任务层面扩展到整个人生层面。
- **来自 life-coach 价值观罗盘**：价值观是罗盘，不是终点（见 `_reference/life-coach/skills/life-vision/references/value-compass.md`）。TELOS 既包含方向（理想状态），也包含起点（当前状态），以及在这段路上「哪些事值得做、哪些事先放下」。

### 1.2 核心理念

```
当前状态（Current State）—— 我现在实际在哪里
           │
           │  差距分析（GAP）
           ▼
理想状态（Ideal State）—— 我想朝哪个方向走
           │
           │  阶段主题（Phase Theme）—— 这一小段路先做什么
           │  不做什么（Not Doing）—— 什么暂时放下
           ▼
      行动与调整
```

**关键区别**：
- **目标**有终点。实现之后，它会变成一个里程碑，然后被新的目标取代。
- **理想状态**没有终点。它是一种持续践行的方向，例如「更健康」「更真实」「更有联结」。
- **阶段主题**是方向在当前时间段的具体化——它定义的是「这一两个月先往哪走」，不是「终点在哪」。

### 1.3 TELOS 不是什么

| 不是 | 说明 |
|------|------|
| 一次性的使命宣言 | TELOS 是动态校准的，不是写一次就永不变的文件 |
| 目标清单 | TELOS 定义的是方向和边界，具体的任务/项目由 ISA 和 planning 承接 |
| 自我批判工具 | 当前状态不是用来批评自己的，是用来确认出发点的 |
| 完美人生蓝图 | 理想状态不是必须实现的完美图景，而是选择方向的参照 |

## 二、TELOS 的核心概念

### 2.1 Current State（当前状态）

**定义**：在每个领域里，我现在实际在什么位置？不是「我觉得我在哪」，而是基于最近真实行为和可观察事实的判断。

**特征**：
- 基于最近 1-4 周的实际行为和感受，不是理想化的自我描述。
- 允许不完美、允许矛盾。当前状态不需要「好看」，需要「真实」。
- 当前状态是出发的起点，不是需要掩盖的缺点。

**示例**：
- 「健康：最近两周运动频率为每周 1-2 次，每次约 20 分钟。睡眠不规律，凌晨 1 点后才睡的情况占一半。」
- 「工作：项目进展符合预期，但连续两周出现下午启动困难。」

### 2.2 Ideal State（理想状态）

**定义**：在这个领域里，我想朝哪个方向走？回答的不是「我要在某月某日达成某个数字」，而是「什么样的状态是我愿意持续靠近的」。

**特征**：
- 方向性而非指标性——不要求精确数字，但要有可感知的方向。
- 来自用户自己的真实渴望，不是「应该」或「必须」。
- 可以调整——方向不必终生有效，但校准前它是有承诺的。

**示例**：
- 「健康：希望建立一种可持续的日常运动习惯，让自己在白天有稳定的精力水平，而不是追求某个体脂率数字。」
- 「工作：希望在做的事情既有专业深度，又能看到实际影响——不只是完成指令。」

### 2.3 Phase Theme（阶段主题）

**定义**：在当前这一小段路（通常是 1-3 个月），我最优先关注的是什么？不是所有领域同时推进，而是选择 1-3 个领域作为重点。

**特征**：
- 阶段性——本阶段主题有明确的预期时长（如「这一季度的主题是重建规律作息」），到期重新评估。
- 排他性——阶段主题意味着把注意力集中在某些领域，而不是均匀分配。
- 可验证——阶段主题结束时，应能判断「在这个方向上我有没有往前走」。

**示例**：
- 「2026 年 Q3 阶段主题：重建睡眠规律和运动习惯。工作保持现有节奏即可，不追求突破。」
- 「2026 年 7-8 月阶段主题：完成职业转型的初步方向确认 —— 收集信息、做 2 个原型实验。」

### 2.4 Not Doing（不做什么）

**定义**：为了把注意力和精力集中在阶段主题上，**什么是我现在主动选择不做的**。不是永远不做，而是这个阶段不做。

**特征**：
- 关联阶段主题——Not Doing 直接服务于阶段主题的聚焦。
- 主动选择——Not Doing 不是「因为做不到所以不做」，而是「因为清楚什么更重要所以选择不做」。
- 减少内耗——明确的 Not Doing 清单可以减少「要不要做」的反复纠结。

**示例**：
- 「在当前阶段主题（重建作息）下，不做什么：
  1. 不启动新的学习项目或课程。
  2. 不在晚上 9 点后安排社交活动。
  3. 不接新的自由职业项目。
  4. 不再反复搜索「最佳睡眠方案」——先执行现有方案。」

## 三、人生 8+1 领域

### 3.1 领域总览

人生被划分为 **8+1 个领域**，覆盖生活的主要维度。每个领域没有固定权重——在不同阶段，不同领域的重要性天然不同。

该结构直接映射自 `templates/profile/life-compass.md` 的人生 8+1 平衡轮。

| # | 领域 | 英文 | 聚焦 | 说明 |
|---|------|------|------|------|
| 1 | 身体与健康 | Body & Health | 睡眠、运动、饮食、医疗 | 身体的物质基础——精力来源 |
| 2 | 情绪与内在 | Emotion & Inner | 心理状态、情绪觉察、内在安顿 | 你与自己相处的方式 |
| 3 | 关系与亲密 | Relationships | 伴侣、家人、朋友、社群 | 你在意的人际联结 |
| 4 | 工作与创造 | Work & Creation | 职业、项目、手艺、创造产出 | 你为世界做的事 |
| 5 | 财务与资源 | Finance & Resources | 收入、支出、储蓄、投资、物质保障 | 维系生活的物质基础 |
| 6 | 学习与成长 | Learning & Growth | 知识获取、技能提升、认知拓展 | 你对未来的投资 |
| 7 | 休息与玩乐 | Rest & Play | 恢复、爱好、游戏、无所事事 | 不只是休息——是活力来源 |
| 8 | 贡献与意义 | Contribution & Meaning | 对他人的帮助、社会参与、超越自我的价值 | 你感到「这很重要」的来源 |
| +1 | 自定义 | Custom | 由用户定义的额外领域 | 当 8 个领域无法覆盖某个重要维度时 |

### 3.2 自定义领域的使用规则

+1 自定义领域用于以下场景：

- 用户有一个强烈的身份承诺，但不属于以上 8 个领域（如「创作者」「照顾者」「修行者」）。
- 用户当前处于一个特殊生命阶段，需要用专属领域来命名（如「孕期」「康复」「gap year」「创业期」）。
- 8 个领域中的某个维度需要被拆分为两个独立方向。

**使用方式**：直接在 `life-compass.md` 或 TELOS 评价表中添加第 9 个领域。当该阶段结束时，可将其合并回 8 个标准领域或移除。

### 3.3 领域的更新频率

- 8 个标准领域的结构通常不需要调整——调整的是每个领域下的内容（当前状态/理想状态）。
- 自定义领域的添加和移除随阶段主题变化：阶段主题变更时评估是否需要自定义领域。
- 不建议在非阶段切换期频繁调整领域结构——因为 TELOS 的价值在于持续跟踪方向变化，而不是每次调整定义。

## 四、每个领域的四维结构

### 4.1 标准格式

每个领域在 `life-compass.md`（或独立的 TELOS 记录）中使用以下四维结构：

```markdown
### {领域名称}

| 维度 | 内容 |
|------|------|
| 当前状态 | {基于最近行为的真实状态描述，1-3 句话} |
| 理想状态 | {想靠近的方向描述，1-3 句话} |
| 阶段主题 | {本阶段在该领域的关注点，0-1 句话（可空：如果本阶段不聚焦该领域）} |
| 不做什么 | {本阶段在该领域主动选择不做的 1-3 件事} |
```

### 4.2 四维结构的关系

```
          ┌──────────┐
          │ 当前状态  │  ← 事实起点（最近 1-4 周的真实情况）
          └────┬─────┘
               │ 差距感：当前和理想之间的落差
               ▼
          ┌──────────┐
          │ 理想状态  │  ← 方向选择（持续靠近的方向，不是终点）
          └────┬─────┘
               │ 阶段聚焦：在本时间段内，这个领域是否优先
               ▼
     ┌─────────────────────┐
     │  是 ──▶ 阶段主题     │  ← 本阶段在这个领域的具体关注点
     │         + 不做什么   │  ← 为了保护主题聚焦而主动放弃的事
     └─────────────────────┘
     └ 否 ──▶ 标记「本阶段不关注」→ 不做什么清单覆盖即可
```

### 4.3 各维度的写作原则

**当前状态写作原则**：
- 以最近 1-4 周的实际行为为依据。
- 允许矛盾——「运动频率不高，但饮食控制得不错」比「运动不行」更有用。
- 避免绝对判断——「偶尔熬夜」比「作息很差」更准确。
- 包含客观数据和主观感受两层面。

**理想状态写作原则**：
- 回答「我想朝哪个方向走」，而不是「我应该在哪个方向」。
- 可以模糊——「想建立更松弛的工作节奏」比「每周工作 40 小时」更真实（但后者在有具体目标时也可以）。
- 允许实验性表述——「我还不确定，但想试试往这个方向走一段时间」。
- 避免完美主义——理想状态不是「最好的自己」，是「我愿意靠近的方向」。

**阶段主题写作原则**：
- 聚焦 1-3 个领域——如果所有领域都有阶段主题，等于没有聚焦。
- 有时间边界——「2026 年 Q3」「7-8 月」「到年底之前」。
- 与 Not Doing 配套——每个阶段主题至少对应 1 条 Not Doing。
- 可评估——阶段结束时能判断「有没有靠近理想状态」。

**不做什么写作原则**：
- 不是遗憾清单——「不做什么」是主动选择，不是「做不到的遗憾」。
- 越具体越好——「不接新项目」比「不加班」更容易执行。
- 关联阶段主题——每一条不做什么都应能直接服务于阶段主题的聚焦。

## 五、更新节奏

### 5.1 更新时机

TELOS 在以下时机更新：

| 时机 | 节奏 | 更新范围 | 说明 |
|------|------|---------|------|
| **每月检视** | 固定（每月初/末） | 当前状态：全领域检查并更新 | 基于上月的实际行为和感受，更新各领域的当前状态 |
| **每季度校准** | 固定（每季初） | 阶段主题 + 理想状态：重新评估和调整 | 上一季度的阶段主题到期，评估进展。设定下一季度的阶段主题和 Not Doing |
| **重大变化时** | 按需 | 全领域或相关领域 | 换工作、搬家、毕业、结婚、生育、重大疾病、家庭变故——这些事件会改变多个领域的当前状态和理想状态 |
| **人生实验结束** | 按需 | 相关领域 | 当 life-vision 流程中的原型实验结束时，实验发现的数据可能更新相关领域的状态判断 |

### 5.2 每月检视流程

每月检视是「轻量维护」——主要更新当前状态，不调整方向。

```
1. 逐领域回顾最近一个月的实际行为和感受。
2. 更新「当前状态」——保持真实，不需要粉饰。
3. 检查「理想状态」是否仍然成立——如果不成立，记录变化原因，作为季度校准的输入。
4. 检查「阶段主题」是否仍然聚焦——如果感觉主题偏移了，不是立即调整，而是标记为「待季度校准」。
5. 在 `profile/life-compass.md` 的更新记录中追加本月条目。
```

**耗时估计**：10-15 分钟（全领域快速回顾）。

### 5.3 每季度校准流程

每季度校准是「方向维护」——重新评估方向、主题和边界。

```
1. 回顾上一季度的阶段主题评估结果：
   - 在阶段主题方向上是否有进展？
   - 上一季度的 Not Doing 是否被尊重了？
   - 对于未执行的领域——是有意识放了，还是忘了？

2. 重新评估所有 8+1 领域的当前状态（基于最近 1-2 个月）。

3. 检查理想状态——是否有需要调整的方向？注意：
   - 理想状态不应频繁变动（否则说明还没找到真实方向）。
   - 如果连续两个季度都在同一个领域反复调整理想状态，这不是方向问题——是需要先做一个 ISA 来澄清。

4. 设定下一季度的阶段主题（1-3 个）。
   - 如果多个领域都需要关注，必须排序——阶段主题就是选择了「先做这个，其他的保持即可」。
   - 为每个阶段主题配套 1-3 条 Not Doing。

5. 更新 `profile/life-compass.md` 的完整版本。

6. 在更新记录中追加季度条目。
```

**耗时估计**：30 分钟（含思考和评估）。

### 5.4 重大变化时更新流程

重大变化发生时（用户主动告知或 Agent 在对话中发现），不需要等待固定的检视时机：

1. Agent 在对话中识别变化信号（换工作/搬家/重大关系变化/健康变化等）。
2. 在当次对话中更新受影响领域的「当前状态」。
3. 询问用户是否需要调整「阶段主题」（如果变化足够大，可能需要）。
4. 如果变化改变了多个领域的状态，建议用户安排一次季度级校准，不必等到季度末。
5. 在 `profile/life-compass.md` 中记录变化。

**与 Tier 系统的关系**：当前状态的更新属于 Tier A（直接写入，基于用户明确表述的事实）。阶段主题的调整属于 Tier C（确认后写入，因为涉及方向变更）。

### 5.5 不做什么的更新节奏

Not Doing 的更新可以更灵活：

- **随阶段主题变化**：阶段主题变更时，Not Doing 应随之更新。
- **随时补充**：如果用户在日常对话中表达了「这个月不想做某事」，Agent 可以立即记录（Tier A/B 取决于上下文）。
- **每月检视时检查**：检视时检查 Not Doing 清单是否仍然有效——如果某个「不做」已经变得自然（不再需要刻意提醒），可以标记为「已自动」并移除。

## 六、ISA 与 TELOS 的关系

### 6.1 ISA 是 TELOS 领域的具体化

`system/isa-system.md` 将 ISA 定义为「一项任务或目标的理想完成状态」。TELOS 与 ISA 的关系是：

```
TELOS（方向层）
  │
  ├── 定义：每个 8+1 领域的当前状态 → 理想状态的方向
  ├── 粒度：整个领域（如「健康」「工作」）
  ├── 更新频率：月/季度
  │
  └── 映射到具体的 ISA（执行层）
        │
        ├── 定义：某项具体任务的完成标准
        ├── 粒度：一个项目、一个实验、一个目标
        ├── 更新频率：按任务生命周期
        │
        └── 示例：
              TELOS：「健康」领域的理想状态是「建立可持续的运动习惯」
              → ISA：「前 4 周跑步入门实验」（将领域方向转化为具体任务）
              → ISA：「午餐结构调整实验」（同一领域的另一个具体化）
```

**ISA 是将 TELOS 领域方向转化为「可验证的具体任务」的桥梁。** 没有 ISA，TELOS 只是一个方向列表——方向需要被转化为可执行、可验证的任务，这就是 ISA 的职责。

### 6.2 从 TELOS 到 ISA 的转化时机

以下信号提示需要为 TELOS 领域的某个方向创建 ISA：

- 用户在某一领域的「当前状态 → 理想状态」方向明确，但不知道下一步做什么 → 创建 ISA 来设计第一个实验。
- 同一领域反复在 TELOS 评价中标记「没有进展」，但没有具体任务在推进它 → 说明领域方向需要被拆分为可执行的 ISA。
- 用户在 life-vision 对话中产出了一个具体的行动计划 → 为该计划创建 ISA。
- 阶段主题确定了某个领域为重点，但该领域的「如何靠近理想状态」路径不清晰 → 先创建 ISA 来探索路径。

### 6.3 ISA 完成后如何反馈到 TELOS

ISA 完成或结束后，其结论应反馈到 TELOS：

1. **ISA 完成**：如果 ISA 定义的任务成功完成，更新相关领域的「当前状态」（Tier A）。
2. **ISA 实验结论**：如果 ISA 是实验性质（如「跑步入门实验」），将其结论更新到相关领域的「当前状态」和「理想状态」（可能需要 Tier B/C 取决于确定性）。
3. **ISA 中断或放弃**：如果 ISA 中途停止，记录原因。这不是失败——这提供了关于「当前状态」的重要数据（如「发现跑步不适合自己」→ 更新健康领域的当前状态）。
4. **ISA 产出洞察**：如果 ISA 执行过程中发现了对领域方向的修正信号（如「原来我想要的不是运动习惯，而是户外时间」），应候选更新「理想状态」（Tier C）。

### 6.4 核心区别总结

| 维度 | TELOS | ISA |
|------|-------|-----|
| **层级** | 方向层（整个领域） | 执行层（单个任务） |
| **回答** | 我想朝哪走 | 怎样算做完 |
| **粒度** | 人生 8+1 领域 | 一个项目/实验/目标 |
| **变化频率** | 月检视/季校准 | 按任务周期（天/周/月） |
| **验证方式** | 自我评估+行为观察 | 可验证声明（verification_method） |
| **谁来维护** | 用户主导，Agent 辅助 | Agent 主导，用户确认 |

## 七、与 life-vision skill 的分工

### 7.1 分工原则

**life-vision 负责对话澄清；TELOS 负责结构化存储。**

| 维度 | life-vision skill | TELOS 系统 |
|------|-------------------|-----------|
| **职责** | 通过对话帮助用户澄清方向、价值观、人生设计问题 | 将澄清后的方向结构化存储为可更新、可跟踪的文档 |
| **工作方式** | 对话式、反射式、探索式（「什么对你重要？」「为什么会卡住？」） | 记录式、结构式、定期检视（四维结构 + 更新节奏） |
| **产出** | 澄清后的方向陈述、价值观线索、人生实验设计 | 更新后的 `life-compass.md` 或 TELOS 记录 |
| **使用时机** | 用户表达迷茫、方向不清、选择困难、人生设计问题 | 每月检视、季度校准、重大变化更新、对话中确认方向性结论后 |
| **输出到** | TELOS 系统（将对话中发现的方向写入 TELOS 结构） | 被 algorithm 的 GAP 分析引用（TELOS 是 Ideal State 的来源之一） |

### 7.2 流程配合

```
life-vision 对话
    │
    ├── 用户说「我最近感觉很迷茫，不知道往哪走」
    │       │
    │       ▼
    │   life-vision 开始对话澄清
    │       │
    │       ├── 使用价值观罗盘提取价值线索
    │       ├── 使用 8+1 平衡轮分领域查看
    │       ├── 生成可能的未来路径
    │       └── 设计小实验来验证假设
    │       │
    │       ▼
    │   对话产出：用户对某个领域有了更清晰的方向感
    │       │
    │       ▼
    └──▶ TELOS 系统
            │
            ├── 将新的方向写入对应领域的「理想状态」
            ├── 更新「当前状态」（基于对话中提到的最近事实）
            ├── 如果对话中设定了阶段性的关注点，写入「阶段主题」和「不做什么」
            └── 如果产出了具体实验，为实验创建 ISA
```

### 7.3 在对话中如何使用 TELOS

**life-vision 技能的工作流程**（见 `_reference/life-coach/skills/life-vision/SKILL.md` 第 4 步）提到：「必要时使用人生 8+1 平衡轮，分领域查看愿景、当前状态和阶段主题。」在实现时：

- life-vision 在对话过程中读取 `profile/life-compass.md`（TELOS 的存储位置），获取用户当前各领域的「当前状态」和「理想状态」，作为对话的背景信息。
- life-vision 的对话结论（澄清后的方向、新发现的价值、阶段主题调整），通过 TELOS 系统写入 `life-compass.md`。
- life-vision 不直接修改 TELOS——它通过对话产出方向性结论，TELOS 负责这些结论的存储、追踪和更新节奏管理。

### 7.4 边界情况

- **life-vision 对话中用户改变了方向**：life-vision 负责在对话中充分探索和确认这个变化（防止冲动决定），确认后由 TELOS 写入更新。遵循 Tier C 规则——方向性变更需要用户确认。
- **TELOS 检视发现领域停滞**：如果月度检视发现某个领域长期没有变化（既未靠近也未远离理想状态），这不是 TELOS 能解决的问题——这是 signal，应触发 life-vision 对话来探索「这个方向还重要吗？还是路径需要重新设计？」
- **用户没有使用 life-vision**：即使没有发生过 life-vision 对话，TELOS 仍然可以通过每月检视和对话中逐步积累的事实来更新。life-vision 对话是 TELOS 方向输入的「深度来源」之一，但不是唯一来源。
