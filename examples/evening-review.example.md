# 晚间复盘邮件交互示例

本示例展示 Life Coach Agent 在工作日 23:00 晚间复盘和前溯日终收尾 17:30 两个时间点的完整交互回合，包括文件变更前后的对比。

## 场景设定

- 用户：小张，产品经理
- 日期：2026-07-29（周三，工作日）
- 当天背景：早上承诺做原型修改（09:30），中途遇到完美主义拖延（15:30 干预），下午状态有所恢复
- 场景覆盖两个时间点：17:30 日终收尾 + 23:00 晚间复盘

## 交互回合一：17:30 日终收尾

### Phase 1: 采集（Gather）

```
[Cron 17:30 触发]
  -> getDayType("2026-07-29") => "workday"
  -> 读取 memory/daily/2026-07-29.md：
     - 09:30 设定核心任务：原型修改
     - 10:30 用户表示"有点卡"
     - 14:30 用户未回复
     - 15:30 完美主义拖延干预：引导定义"最低可接受版本"
     - 用户后续未回复（是否完成未知）
  -> 读取 profile/user.md：沟通偏好，低精力时段提示
  -> 发送决策：正常发送，使用日终收尾模板
```

### Phase 2: 触达（Reach）

**Agent 发送的邮件：**

```
主题：今天收工前，三个快速问题

小张，下午好。在结束今天主要工作之前，花一分钟想三个问题：

1. 原型修改有进展吗？哪怕只挪了一个按钮也算。
2. 哪件事还没做完，需要明天继续？
3. 现在状态怎么样——需要休息了，还是可以再做一点？

不用回很长。三个字、一句话都可以。
```

### Phase 3: 接收（Receive）

**用户回复（邮件内容）：**

```
1. 放弃推倒重来的念头了，最后定了一个能看的版本，交互跑通了。没有完美但是能用。
2. 评审会材料明天早上补看，今天来不及了。
3. 有点累，但比下午好多了。准备收拾回家。
```

### Phase 4: 理解（Interpret）

```
[理解阶段]
  -> 用户在 15:30 干预后成功突破了完美主义卡点
  -> 完成了"最低可接受版本"，交互跑通是实质性进展
  -> 评审会材料推迟到明早是合理选择（会前 15 分钟足够，见早上判断）
  -> 精力状态：下午走神，但完成收尾后尚可
  -> 无强烈情绪信号，不需要切换到 CLI/Chat
```

### Phase 5: 行动（Act）

**Agent 执行以下操作：**

1. 更新 `memory/daily/2026-07-29.md`，记录日终状态
2. 为 23:00 的晚间复盘做标记（今天有值得在晚间展开的议题：完美主义卡点及其突破）
3. 发送确认邮件

**`memory/daily/2026-07-29.md` 新增内容：**

```markdown
## 17:30 日终收尾

- cron_slot: wrap_up
- channel: email
- 用户回复时间: 17:35
- 今日核心任务状态: 原型修改 -> 完成「最低可接受版本」，交互跑通
- 未完成: 评审会材料（推迟到明早）
- 用户自评: "没有完美但是能用"
- 精力状态: 下午有走神，但 15:30 干预后恢复，收尾时状态可接受
- 晚间复盘议题标记: 完美主义卡点与突破过程值得复盘——什么让用户最终放下了"推倒重来"？
```

### Phase 6: 闭环（Close）

**Agent 发送确认邮件：**

```
主题：很好，"能用"比"完美"重要得多

小张，收到。

交互跑通了就是重大进展。明天你觉得哪里不顺可以再改，但今晚你带着一个能跑的版本回家。

今晚 23:00 我会再问你几个问题——不急着回，睡前看一眼就行。

好好休息。
——Life Coach Agent
```

## 交互回合二：23:00 晚间复盘

### Phase 1: 采集（Gather）

```
[Cron 23:00 触发]
  -> getDayType("2026-07-29") => "workday"
  -> 读取 memory/daily/2026-07-29.md（整合全天记录）：
     - 09:30: 晨间启动，选择优先原型修改
     - 10:30: 上午卡住
     - 14:30: 下午继续未推进
     - 15:30: 拖延干预，定义最低可接受版本
     - 17:30: 日终收尾，完成可跑版本
  -> 读取 profile/user.md：用户偏好、复盘习惯
  -> 读取 memory/long-term.md：用户历史复盘模式
  -> 发送决策：正常发送，使用晚间复盘模板
```

### Phase 2: 触达（Reach）

**Agent 发送的邮件：**

```
主题：今天过得怎么样？一起回顾五分钟

小张，今天辛苦了。

睡前花五分钟，问自己几个问题：

1. 今天你最满意的一个时刻是什么？
2. 今天有没有什么地方和预期不一样？
3. 今天最消耗你精力的是什么？
4. 如果明天只改一件事，你会改什么？

想到哪个就先回哪个，不用全部答。
```

### Phase 3: 接收（Receive）

**用户回复（邮件内容）：**

```
1. 下午决定不推倒重来的时候，松了口气。接受"能用"比我想象的容易。
2. 没想到改个原型能耗一整天，最初以为上午就能搞定。
3. 反复改同个页面最消耗精力。改到后来眼睛都分不出哪个版本好。
4. 明天先做需要创造力的活，把评审会材料这种"扫一眼就行"的事放碎片时间。
```

### Phase 4: 理解（Interpret）

```
[理解阶段]
  -> 用户识别出今天的关键觉察：
     a. 完美主义螺旋的停止点（"接受'能用'比想象容易"）
     b. 时间预估偏差（"以为上午就能搞定"耗了一整天）
     c. 精力陷阱（反复修改导致视觉疲劳，无法判断好坏）
     d. 任务排序策略（创造力优先 > 信息处理）
  -> 这些觉察有长期价值，值得写入 memory/long-term.md
  -> 用户回答质量较高（非敷衍），说明晚间复盘对其有效
  -> 不需要额外行动，本次对话的闭环即记录觉察
```

### Phase 5: 行动（Act）

**Agent 执行以下操作：**

1. 更新 `memory/daily/2026-07-29.md`，记录晚间复盘内容
2. 更新 `memory/long-term.md`，沉淀跨会话洞察
3. 发送确认邮件

**文件变更前后对比：**

`memory/daily/2026-07-29.md` 新增内容：

```markdown
## 23:00 晚间复盘

- cron_slot: night_review
- channel: email
- 用户回复时间: 23:08

### 用户回答
1. 最满意时刻: 下午决定不推倒重来的那个瞬间——发现自己可以接受"能用"而不是"完美"
2. 与预期不一致: 原型修改耗了一整天，远超预估（上午说 25 分钟改一个东西，实际花了 7+ 小时）
3. 最消耗精力: 反复修改同一页面，视觉疲劳后无法区分好坏
4. 明天改一件事: 创造力任务优先排在上午，信息处理类任务放碎片时间

### 提取觉察
- **完美主义突破点**：用户发现"接受能用"的情绪代价比预期小，可成为下次卡住的参考锚点
- **时间预估偏差**：原型修改类任务用户有系统性低估倾向（预估上午 -> 实际全天），后续计划需预留 2-3x 缓冲
- **精力陷阱**：视觉/审美类任务反复修改会导致决策疲劳，需要设置"修改次数上限"或"冷却时间"
- **任务排序策略**：用户自发提出"创造力优先"的排序原则，与上午记录的执行线索一致
```

`memory/long-term.md` 变更前：

```markdown
## 执行模式

- 2026-07-28: 下午 3 点后精力明显下降，适合安排低认知任务
```

变更后：

```markdown
## 执行模式

- 2026-07-28: 下午 3 点后精力明显下降，适合安排低认知任务
- 2026-07-29: 原型/设计类任务存在系统性时间低估（预估上午 -> 实际全天），预留 2-3x 缓冲
- 2026-07-29: 完美主义卡点时，"接受能用的版本"的阻力比预期小——可作为后续干预锚点
- 2026-07-29: 视觉/审美类任务设置"修改次数上限"（如最多 3 版），超限后需冷却 30 分钟再看

## 有效策略

- 2026-07-29: 用户自发提出"早上做创造力任务，碎片时间做信息处理"的排序原则——与精力曲线吻合
```

### Phase 6: 闭环（Close）

**Agent 发送确认邮件：**

```

小张，晚安。

今天有三个东西值得记住：
1. 你证明了自己能在卡住之后转回来——下午那个"不推倒重来"的选择是今天的转折点。
2. 原型修改比预估费时——下次类似任务我会帮你多留一倍时间。
3. 早上创造力优先、碎片时间信息处理的排序，是你自己悟出来的好办法。明天按这个来。

今天的复盘会记在长期记忆里，下次你卡在类似的地方，我会提醒你：上次你接受了"能用"，结果并不差。

好好睡觉，明天见。
——Life Coach Agent
```

## 这个示例展示的能力

- 晚间复盘是全天信息的整合点：不只看当天做了什么，更看"从今天学到了什么"
- 复盘不追求全面，追求"捕捉关键觉察"——用户今天最重要的学习是"接受能用比想象容易"
- 从单日观察中提取长期规律：时间预估偏差、完美主义突破点写入 long-term.md
- 复盘确认邮件不是流水账，而是帮助用户命名和锚定今天的关键学习
- 日终收尾（17:30）和晚间复盘（23:00）的分工：日终重"事实记录"，晚间重"觉察提炼"
- 记忆系统"先记录再提炼"原则的示范：daily 记录具体事实 -> long-term 沉淀跨会话模式
