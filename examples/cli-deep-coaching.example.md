# CLI/Chat 深度教练交互示例

本示例展示用户通过 CLI/Chat 通道发起深度教练对话的完整交互回合：用户主动提问 -> Agent 识别深度需求 -> 多轮对话 -> 达成觉察 -> 文件写入 -> 对话收尾。

与邮件通道不同，CLI/Chat 支持实时多轮追问、深度情绪承接和复杂问题拆解，适合邮件无法处理的场景。

## 场景设定

- 用户：小张，产品经理，29 岁
- 通道：CLI/Chat（用户主动发起）
- 日期：2026-07-29（周三，晚上 21:00）
- 触发方式：用户主动发起对话（非 Cron 触发）
- 背景：白天用邮件完成了日常打卡，晚上用户想做一次深度思考

## 交互回合

### 用户开场

```
用户: 我最近一直在想一个问题——我现在做产品经理快五年了，但我越来越不确定这是不是我想一直做下去的事。不是不喜欢，但总觉得少了点什么。
```

### Agent 识别与路由

```
[Agent 内部推理]
  -> 用户表达了方向性困惑（"不确定是不是想一直做下去"）
  -> 不是简单的执行或计划问题
  -> 涉及人生方向、价值观、身份主题 -> 路由到 life-vision skill
  -> 属于深度对话需求，CLI/Chat 是正确的通道
  -> 开始前先建立安全：用户需要空间表达，而不是立刻给答案
  -> 读取 life-vision/references/value-compass.md 和 workflow.md
  -> 读取 profile/user.md 获取用户背景
```

### Agent 第一轮回应

```
Agent: 我先不急着帮你分析"该不该继续做产品经理"。我们先换个角度——

你刚才说"不是不喜欢，但总觉得少了点什么"。这个"少了点什么"，你能试着多说一点点吗？不需要找到答案，只需要描述它给你的感觉。

比如：是少了兴奋感？少了意义感？少了成长空间？还是别的东西？
```

### 用户第二轮

```
用户: 好像是少了意义感。我现在做的产品是给企业做内部管理系统，功能都能做，用户也满意，但我觉得这些东西——说不上来——好像换个人也能做。我做得好不好，对这个世界差别不大。
```

### Agent 第二轮回应

```
Agent: 我听懂了。不是做不好，而是做得好不好对世界的影响差别不大。这让你觉得自己的努力没有"着陆"——落在了功能上，但没有落在你关心的事情上。

那我想问另一个方向：如果抛开现在的产品经理身份，在过去的任何时刻——工作里、生活里、业余项目里——你有没有做过什么让你觉得"这件事我做了和没做，真的不一样"？
```

### 用户第三轮

```
用户: （想了一会儿）...有的。我去年帮一个朋友的创业团队梳理过他们的产品方向。他们技术很强但完全不懂用户，我帮他们做了用户访谈、理了需求优先级。后来那个产品上线了，朋友说如果没有我，他们至少要多绕半年弯路。那个感觉挺好的——我知道我的经验真的帮到了一群想做点事情的人。
```

### Agent 第三轮回应

```
Agent: 这是很重要的线索。我们把它拆开看：在那个场景里，和你在企业里做内部系统，有哪些不一样？

我猜，至少有这几个维度可以对比：
A. 影响力——帮创业者做对了，产品能活下来；帮企业内部做系统，最差也就是效率低一点
B. 关系——帮朋友是真实的、具体的、有反馈的；做内部系统更多是"需求方"和"执行方"
C. 自主性——帮朋友的时候，你是从零开始搭方向；做内部系统的时候，方向大多是上面定的

这些拆解有说中你吗？有没有漏掉的？
```

### 用户第四轮

```
用户: B 和 C 说中了。C 尤其对——我现在哪怕做到 senior，大部分时间还是在接需求、排期、交付。我想做的是"定义方向"，但现在做的是"执行方向"。

可是我又不确定：是不是我太矫情了？现在工作稳定、待遇也不错。一定要做"有意义"的事吗？是不是很多人也都这样？
```

### Agent 第四轮回应

```
Agent: 你提了两个不同层面的问题，我们分开看。

第一个问题："一定要做有意义的事吗？"
这不是一个可以被别人回答的问题。但我们可以换个问法：如果五年后的你回头看今天，你会希望自己当时做了什么——是继续在稳定轨道上往前走，还是在某个时间点转了个弯？这个答案只有你知道。

第二个问题："是不是我太矫情了？"
不是。你已经在一个领域积累了五年，当你说"想做定义方向的活"的时候，这不是矫情，是你对自己的能力有了更准确的判断。你知道自己不只是会执行，你也能判断方向——但你现在的环境没给你这个空间。不是你的问题，是环境和你之间的不匹配。

我先不逼你回答第一个问题。第二个问题我们已经有答案了：不矫情，是合理的。
```

### 用户第五轮

```
用户: 谢谢——"环境和我之间的不匹配"这个说法让我好受很多。不是我不行，是现在的环境和我要的不一样。

那我接下来该怎么做？我总不能明天就辞职去帮创业团队吧。
```

### Agent 第五轮回应

```
Agent: 当然不是明天。但我们可以设计一个小实验——既不需要辞职，又能让你测试一下"做定义方向的活"是不是真的比现在更让你满足。

给你几个选项，你看看哪个更贴近你现在能做的：

A. 在现有工作里找一个缝隙——有没有一个内部小项目，可以让你从需求分析做到方向定义，而不是纯执行？哪怕很小，哪怕只占你 20% 的时间。

B. 业余时间帮一个朋友/副业项目做方向顾问——就像你去年做的那样，但更刻意地把它当作一个"实验"而不是"帮忙"。记录每次做的时候的感受。

C. 做一次信息访谈——找 2-3 个从执行转向方向的 PM 聊聊，问他们怎么转的、最难的是什么、回头看不后悔的是什么。

不急着选。这些选项的共同点是：不辞职、低风险、能产生关于你自己的真实数据。你要的不是一个"正确选择"，而是一组能帮你判断的反馈信号。
```

### 用户第六轮

```
用户: 我想试试 B。有一个大学同学在做教育类产品，前两周还找我问过产品规划的事。我可以认真帮他做一次，同时记录我的感受。

但我也想问：如果做到一半我发现"这确实是我更想要的"，下一步是什么？
```

### Agent 第六轮回应

```
Agent: 好问题。但我想先按住你的这个冲动——你已经开始跳步骤了。

你现在还不需要"如果确认了方向之后怎么办"的答案。你需要的是"怎么确认方向是不是真的"的方法。这两个是不同的问题。

你现在的任务只有一个：帮同学做一次产品规划，然后认真记录：
- 做的时候，注意力是高度集中还是散的？
- 做完之后，是充实还是空虚？
- 你愿不愿意免费做这件事？

这些数据比任何推理都准。拿到数据之后，我们再来讨论下一步。

在那之前，"下一步"是提前焦虑，不是提前准备。
```

### 用户第七轮

```
用户: 哈哈好吧，你说得对。我又在提前焦虑了。那我先去做 B——帮同学做产品规划。我该具体记录什么？
```

### Agent 第七轮回应

```
Agent: 记录三个东西就够了：

1. **投入度**（做的时候）：你的注意力质量如何？有没有进入过心流？时间过得快还是慢？
2. **恢复感**（做完之后）：你是觉得被消耗了，还是觉得有能量？会不会想接着做下一件事？
3. **意义判断**（隔天再看）：你愿不愿意免费再做一次？如果愿意，说明这件事本身对你有价值。

每次做完记录在 memory/daily/ 里，格式随意。攒够 3 次，我们再一起对比看看。

---

我把今天的对话要点记录到你的长期记忆中，方便下次接着讨论。你需要确认一下：

1. 当前阶段：在 PM 执行岗工作了近 5 年，开始产生方向层面的不满足感。
2. 核心需求：想做"定义方向"的活，而不是"执行方向"。
3. 关键线索：帮朋友梳理产品方向的经验给了你很强的意义感和影响力感。
4. 下一步实验：帮大学同学的创业项目做产品规划，用投入度+恢复感+意义判断三个维度记录感受。
5. 暂挂问题：如果确认方向后怎么办——等实验数据再说。

这些对吗？有没有需要修正的？
```

### 用户第八轮

```
用户: 对。没问题。谢谢你今晚陪我聊这些。感觉好像一直有答案在里面，就是没被问出来。
```

### Agent 第八轮回应（收尾）

```
Agent: 你的话里有答案——我的工作是帮你把它们找出来、擦干净、摆在面前。

今晚你最大的觉察不是"我该不该辞职"，而是"我至少可以先做个实验"。这是很重要的转变：从不许自己试，到允许自己用一个低风险的方式去验证。

去做吧。帮同学做产品规划的时候别想太多，就当是一个认真的实验。数据会告诉我们下一步。

下次你想聊的时候随时叫我。或者过两周我问你实验进展。
——Life Coach Agent
```

## CLI/Chat 与邮件的分工总结

| 维度 | 邮件（本日其他示例） | CLI/Chat（本示例） |
|------|---------------------|---------------------|
| 触发方式 | Cron 定时触发 | 用户主动发起 |
| 对话深度 | 单轮或少量轮次，每次一个核心问题 | 多轮深入，可即时追问和澄清 |
| 适合场景 | 日常打卡、状态采集、轻量推进 | 强情绪承接、价值澄清、行为设计、复杂问题拆解 |
| 问题类型 | 选项式、封闭式确认 | 开放式探索、觉察促进 |
| 回复节奏 | 异步，用户可在方便时回复 | 同步或近同步，实时对话 |
| 情绪承接 | 轻量映照，出现强情绪时引导切换 | 实时承接，多轮稳定和逐步深入 |
| 知识写入 | 事实记录为主 | 觉察和长期洞察为主 |
| 字数约束 | 单封邮件不超过 200 字 | 无硬性约束，但保持简洁 |

## 这个示例展示的能力

- 深度教练对话的完整结构：建立安全 -> 映照情绪 -> 澄清需求 -> 促进觉察 -> 设计实验 -> 收尾总结
- 区分用户的"问题"和"问题背后的问题"——用户问"该不该辞职"，实际需要的是"如何验证方向是否正确"
- 识别并命名情绪：不是"矫情"，是"环境和个人发展的不匹配"
- 打断用户的提前焦虑：在拿到实验数据之前不做下一步决策
- 小实验设计：低成本、低风险、高反馈——帮朋友做一次产品规划
- 实验记录维度：投入度、恢复感、意义判断——可量化、可对比
- 对话收尾做确认性总结：列出 5 个要点让用户校验，确保理解一致
- 写入长期记忆时区分"稳定画像"和"实验阶段"——不把推测写成长期事实
- ACT 底层原则的体现：认知解离（"矫情"这个标签被重新框架）、价值澄清（帮朋友=意义感）、承诺行动（设计实验）
