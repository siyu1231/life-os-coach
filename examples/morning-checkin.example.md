# 晨间启动完整邮件交互示例

本示例展示 Life Coach Agent 在工作日 09:30 晨间启动的完整交互回合：Cron 触发 -> 邮件发送 -> 用户回复 -> Agent 处理 -> 确认邮件 -> 文件变更前后对比。

## 场景设定

- 用户：小张，产品经理，工作日 09:00 到公司
- 日期：2026-07-29（周三，工作日）
- 触发时间点：09:30（Fixed Cron）
- 通道：企微邮件

## 交互回合

### Phase 1: 采集（Gather）

```
[Cron 09:30 触发]
  -> getDayType("2026-07-29") => "workday"
  -> 读取 profile/user.md：小张，09:00 到公司，高能量时段 09:00-12:00，今日待办：需求评审、原型修改
  -> 读取 memory/daily/2026-07-29.md：今日尚无记录
  -> 读取 memory/daily/2026-07-28.md：昨日主要完成了数据看板迭代，22:30 复盘提到"今天效率还行，但下午 3 点后明显走神"
  -> 读取日历 API：09:30 无会议，10:00-11:00 需求评审会，14:00-15:00 技术方案讨论
  -> 读取待办 API：今日 7 个待办，其中 2 个已标记高优先级
  -> 读取天气 API：北京，晴，28-35°C
  -> 发送决策：正常发送
```

### Phase 2: 触达（Reach）

**Agent 发送的邮件：**

```
主题：周三早安 | 今日关注 3 件事

小张，早上好。北京今天晴，28-35°C。

你今天有 7 个待办，10:00 需求评审会。
昨天复盘提到下午容易走神，今天下午的安排可以轻一点。

今天最想推进的 1-2 件事是什么？
A. 先把评审会材料过一遍
B. 上午集中搞原型修改
C. 有其他想法

选一个告诉我，剩下的我来帮你排。
```

### Phase 3: 接收（Receive）

**用户回复（邮件内容）：**

```
选 B。原型改了好几版了，今天想收掉。但评审会材料也还没看，有点焦虑。
```

**Agent 解析：**
- `mailid`: msg_20260729_094201_a3f2
- `reply_to_mailid`: msg_20260729_093000_b1c4（Agent 发送的邮件）
- `content_classification`: `task_priority`（用户在排优先级）
- 用户情绪信号：焦虑（"有点焦虑"）

### Phase 4: 理解（Interpret）

```
[理解阶段]
  -> 用户选择了 B（原型修改），但提到 A（评审会材料）带来的焦虑
  -> 分类：multi_task_anxiety（多任务焦虑）
  -> 路由到 planning skill 的 mail-trigger
  -> 判断：无需切换到 CLI/Chat，属于邮件可处理的轻量任务排期问题
  -> 需读取 profile/user.md 中的执行线索：用户偏好"先啃硬骨头"但容易过度承诺
```

### Phase 5: 行动（Act）

**Agent 执行以下操作：**

1. 读取 `planning/daily-plan.md` 获取今日计划模板
2. 更新 `memory/daily/2026-07-29.md`，写入今日首次接触记录
3. 生成确认邮件
4. 设置 +5min 动态 Timer

**文件变更前后对比：**

`planning/daily-plan.md` 变更前：

```markdown
## 今日计划 (2026-07-29)

### 上午
- [ ] 需求评审会准备 @10:00
- [ ] 原型修改 #2

### 下午
- [ ] 技术方案讨论 @14:00
- [ ] 数据看板优化跟进
```

变更后：

```markdown
## 今日计划 (2026-07-29)

### 上午
- [ ] 需求评审会准备 @10:00（会前 15 分钟快速过即可）
- [x] ~~原型修改 #2~~ -> 确定为今日核心任务，上午聚焦

### 下午
- [ ] 技术方案讨论 @14:00
- [ ] 数据看板优化跟进

### 今日洞察
- 09:42 用户选择优先推进原型修改，评审会材料只需会前 15min 扫一眼
- 用户表达了焦虑，可能源于过度承诺倾向 -> 下午只排 1 件核心任务
```

`memory/daily/2026-07-29.md` 新增内容：

```markdown
## 09:30 晨间触达

- cron_slot: morning
- channel: email
- 用户回复时间: 09:42
- 用户选择: 优先原型修改
- 情绪信号: 轻度焦虑（担心评审会材料）
- 行动: 调整今日计划，降低评审会准备优先级，确认为会前 15 分钟快速浏览即可
- 备注: 用户偏好"先啃硬骨头"，但需防止过度承诺。下午仅保留 1 个核心任务
```

### Phase 6: 闭环（Close）

**Agent 发送确认邮件：**

```
主题：好的，原型优先

小张，收到。

上午聚焦原型修改。评审会的材料不着急——会前 15 分钟快速扫一眼就够了。
下午只留技术方案讨论，数据看板推明天。

我会在 10:30 问你进度。加油。

——小芽
```

---

## 这个示例展示的能力

- Cron 系统按工作日 09:30 自动触发，采集当日上下文（日历、待办、天气、昨日复盘）
- Agent 发送的邮件包含上下文简述、一个核心问题、2-3 个可选回复方向，纯文本不超过 200 字
- 用户回复后，Agent 解析邮件内容、分类用户意图、识别情绪信号
- Agent 根据用户回复更新 today's daily-plan 和 memory/daily
- 确认邮件中给出具体的下一步行动建议，并以可执行收尾结束
- 6 阶段状态机完整走完：采集 -> 触达 -> 接收 -> 理解 -> 行动 -> 闭环
